# V4.1: dark-first visual system

The same structure, interactions and content as V4 (concepts/v4), with a new visual system. Branch `profile`; not deployed.

- Palette: #101318 base, #191E25 secondary, #242B33 surfaces, #F0EDE7 / #A7AFB9 type, teal for L//IOS only, amber for the one thing to notice, ivory #EDEBE6 for two rooms (the tools and Beyond). Roughly three-quarters dark by scroll length.
- Hero: a dark bench lit by a lamp that follows the cursor. Letters have a hairline edge and a shadow that lengthens with height (`--lift`, set in kinetic.js). Spare pieces of type (? & → { } %) rest on the right; you can pull them and they spring back.
- How I think: an object study in a dark room, lit from above. Gradient materials per face (top/left/right), lit and shaded edges, a soft contact shadow that thins as the parts lift, a pool of light, and a masked architectural grid.
- What I can do: the ivory room. The three tools are dark application windows (title bar, toolbar, sticky table header); the tools' chart colours are re-scoped so the same JS draws for a dark surface.
- L//IOS: a full-width stage for the real screens with teal stage light, a deep window shadow, the wordmark wiping in, tab changes as a cut-and-settle (blur → sharp), and screenshot swaps that cross-fade.
- Beyond: the warm room. A sticky headline and pull quote beside the contents list.
- Background: a quieter #191E25 room. Close: dark, the line assembles, an amber rule draws out, then contact.
- Checks: packed file has no console errors, no horizontal overflow at 1440/390/360, reduced motion loads, every control has a name. Desktop and phone screenshots reviewed; refinements: removed horizon hairlines that cut through the headline and the object, and added the spare type to balance the empty right side of the hero.
